Certificate Validation & Timestamping

Business: Subidha Furniture  |  Document ref: SF-LEGAL-CERT-001  |  Version: 1.0  |  Date: July 2026  |  Classification: PRIVATE — Internal compliance record
Current Status: READY — Not Yet Activated Subidha Furniture has prepared this policy in readiness for digital eSign. Digital eSign (DSC / Aadhaar eSign) is not currently active. All high-assurance contracts currently use physical wet-ink signatures (Tier A per SF-LEGAL-SIG-001). This document will become operative when a CCA-accredited eSign provider subscription is obtained and activated.

1. Purpose

When digital eSign is activated, this document governs how Subidha Furniture validates certificate chains, checks certificate revocation status, and captures RFC 3161-compliant timestamps on all digitally signed documents. This ensures that digitally signed agreements are legally valid under the IT Act 2000 and the Information Technology (Certifying Authorities) Rules 2000.

2. Planned eSign Provider Requirements

When a provider is selected, it must meet all of the following before activation:

  • Licensed / accredited by the Controller of Certifying Authorities (CCA), India
  • Supports Aadhaar-based eSign (offline XML / OTP) or DSC-based signing
  • Provides RFC 3161 compliant timestamp tokens with each signed document
  • Provides an OCSP (Online Certificate Status Protocol) or CRL (Certificate Revocation List) endpoint for real-time certificate validation
  • Returns certificate serial number, issuing CA name, validity window, and signature hash in the signing receipt
  • Provides sandbox / staging environment for pre-production testing

4. Pre-Activation Checklist

Before digital eSign is used on any live customer agreement, all of the following must be completed:

  1. Select and subscribe to a CCA-accredited eSign provider
  2. Complete sandbox integration and test with at least 5 test signings
  3. Verify OCSP/CRL endpoint is responsive and returns correct status
  4. Verify RFC 3161 timestamp token is attached to each test document
  5. Confirm audit log captures all fields in the table above
  6. Update the Signature Tiering Policy (SF-LEGAL-SIG-001) to add Tier A-Digital
  7. Update this document with the provider name, sandbox logs, and activation date
  8. Obtain CA/advocate sign-off on the updated document
  9. Upload updated document to the compliance system and re-approve
